# 偏移维护指南（给以后更新维护的 AI / 贡献者）

> 目标读者：游戏更新后，需要为新版本重新适配内存偏移的人（大概率是 AI）。
> 读完本文 + `docs/特征重定位思路.md` 即可独立完成适配，无需其他上下文。

## 1. 背景速览

国服和谐 = 服务器按账号下发家长控制标志 → 客户端强制开启"降低暴力程度"（Teen 模式）并隐藏选项。**未和谐资源就在本地**。工具的反和谐 = 三段内存写：

| 偏移 | 内容 | 作用 |
|---|---|---|
| `nop_sites` ×3 | `(偏移, 原始字节)`，如 `0x11D9F0 / 742A`（jz 条件跳转） | NOP 掉三处"CHN 条件"判断，解除选项隐藏/锁定（恢复时写回原始字节） |
| `store` | `0x3E2E381` | "减少暴力表现"的存储位（CVariableT\<bool\> 值内嵌）：0=未勾选（完整特效）、1=勾选（和谐） |
| `r` | `0x3E2B5A8` | R 三态：0=和谐 1=完整 2=CHN/ROK 强制 |

偏移都是 **SC2_x64.exe 模块内偏移**（运行时真实地址 = 模块基址 + 偏移）。基址由 pymem 动态获取，**偏移本身写死**，因此绑定游戏版本。

**重要约定**：Ghidra 里看到的地址（如 `0x14011D9F0`）减去默认映像基址 `0x140000000` = 模块内偏移（`0x11D9F0`）。

## 2. 偏移文件 offsets.dat（app 同目录，JSON 内容 .dat 后缀）

```json
{
  "_说明": "……自文档字段……",
  "versions": {
    "5.0.15.32043": {
      "display": "5.0.16.97579",
      "nop_sites": [["0x11D9F0", "742A"], ["0x11D9F9", "7421"], ["0x11DA02", "7518"]],
      "store": "0x3E2E381",
      "r": "0x3E2B5A8"
    }
  }
}
```

- **键 = exe 内嵌版本号**（不是战网显示号！启动时工具读 `SC2_x64.exe` 的版本资源来查表；战网/补丁器显示的版本号与 exe 内嵌版本**不同步**，已知映射：战网 `5.0.16.97579` ↔ exe `5.0.15.32043`）。
- `display` = 战网显示版本号，仅用于日志/界面显示，让用户对照战网不困惑。
- 加载规则（见 `get_pm()`）：exe 版本在文件里有条目 → 用文件偏移；没有 → 回退程序内置偏移（5.0.15/5.0.16 前缀）；都没有且 `config.check_version=true` → 拒绝内存操作并提示。
- 文件损坏/格式错误 → 忽略并回退内置偏移，不影响启动。**注意**：条目格式错误
  （比如 nop_sites 里字节写成非十六进制）会被当作"这个版本没有可用偏移"，
  于是走版本核对——若该版本不在内置支持列表，就会**拒绝内存操作**（这是刻意的：
  绝不能用内置的旧版偏移去写新版本）。写新条目后请确认日志里出现
  "已从 offsets.dat 载入 X 的偏移"，没有这行说明条目没被采用。
- 后缀刻意用 `.dat` 防误改，内容就是标准 JSON。

## 3. 新版本适配流程（推荐顺序）

### 第 0 步：确认偏移是否真的变了
先**别急着逆向**。把新版本游戏跑起来，用工具的只读手段验证旧偏移是否仍然有效：
1. `app/sc2_uncensor.py` 的 `get_pm()` 临时放行新版本（或在 `offsets.dat` 先原样复制旧条目、键改为新 exe 版本号）。
2. 按 F11（自动切换）：若存储位按预期翻转、游戏画面同步变化 → **偏移没变**，只更新 `display`/版本键即可收工。
3. 若点击"未命中"或存储位不变 → 偏移确实变了，进入第 1 步。

### 第 1 步：状态差分法定位存储位（最快，无需 Ghidra）
参照 `workspace/phase1/state_diff2.py` / `scan_flag.py` 的思路：
1. 挂载新版本，`pm.read_bytes(base, 模块大小)` 全模块快照存档。
2. 在游戏里通过 UI 正常勾选/取消"减少暴力表现"各一次（对局外），期间连续快照做差分。
3. 只在勾选状态翻转时**恰好翻转一个 bit** 的地址就是新的 `store`（用两轮 勾选→取消 交叉验证，排除噪声地址）。
4. `r` 的定位同理：监视三态变化（和谐/完整切换时 0↔1）。

### 第 2 步：NOP 三处的定位（两条路线任选）
- **路线 A：Ghidra（重 but 稳）**：按 `prompts/03_阶段3_写入者分析与AOB.md` 流程，用字符串锚点（"家长控制"相关 UI 文案 / CVar 名）找写入者函数，分析三处条件跳转。原始字节记下来（restore 功能要用）。
- **路线 B：旧版本特征平移（轻）**：在旧版本里取每个 NOP 点前后 32 字节做特征，用 CE / 自写扫描器在新版本 .text 里搜。SC2 处于维护期，小补丁通常指令排布不变，特征大概率原样命中——命中后核对周边指令语义是否一致再写。

### 第 3 步：验证（必须）
1. `offsets.dat` 填入新条目 → 启动工具（连接日志应显示"已从 offsets.dat 载入 … 的偏移"）。
2. F9 全自动跑一遍：两次"命中OK"+ 游戏画面切换完整特效。
3. Ctrl+Alt+4（关闭反和谐·自动）跑一遍：恢复原状。
4. F11 反复切换 3 次无异常。
5. 提交 `offsets.dat` 新条目（顺带更新 `display`）。

## 4. 常见坑

- **exe 内嵌版本号 ≠ 战网版本号**（见第 2 节），offsets.dat 的键一定用前者。
- 存储位是 CVar 值**内嵌**在模块数据区，不在堆上；别去找指针链。
- 写 NOP 时**必须同时记录原始字节**，关闭反和谐功能依赖它。
- 该存储位不写 `Variables.txt`（改配置文件无效），必须走内存 + UI 点击触发。
- 对局内选项蒙灰：点击无效属正常（工具已有三层防护），验证请回主界面。
